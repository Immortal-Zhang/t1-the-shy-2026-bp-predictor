# Data provenance and import contract

The training records are downloaded match CSVs, not generated examples. Unit tests use explicitly labelled structural fixtures; those fixtures are never written to `data/raw` or used by the real training command.

## Current source snapshot

- Provider: [ChainCC open dataset](https://chaincc.lol/free/data/).
- Source methodology: [ChainCC methodology](https://chaincc.lol/about/methodology). Its historical drafts and scoreboards derive from Oracle's Elixir. This project uses raw CSV observations, never ChainCC's retrospective hero/composition scores.
- Download date: 2026-10-22. The page advertised a 2026-10-21 update. The actual downloaded CSVs stop at **2026-10-18 19:48:36 UTC**, under the documented UTC interpretation of their timezone-free source dates.
- Published license: **CC BY 4.0**, requiring attribution. Suggested attribution: “ChainCC. League of Legends esports match dataset. https://chaincc.lol/free/data/ (accessed 2026-10-22).” Underlying Riot intellectual-property rights are not transferred by this project.
- Each file's exact URL, SHA-256, row count, local retrieval timestamp, size and date range is recorded by `download_data` in `data/raw/sources.json`. For the two initially downloaded 2026 files, filesystem modification times are explicitly identified as the timestamp basis.
- Original downloaded files are retained locally and excluded from Git. Accepted and quarantined counts are generated by the program in `data/processed/quality_report.json`; quarantined game IDs and reasons are in `data/processed/quarantine.csv`.

## Actual field inspection

The player CSV has `game_id,date,league,year,split,playoffs,patch,team_name,opponent_team_name,side,position,playername,champion,result,gamelength`, followed by combat/economy/vision/objective-derived statistics. **It has no `player_id` or `playerid`.**

The team CSV has `game_id,date,league,year,split,playoffs,patch,game_number,bo_format,match_in_series,game_in_match,side,team_name,team_id,opponent_team_name,result,gamelength,first_pick,ban1..ban5,pick1..pick5`, followed by postgame statistics. `first_pick` is read independently of `side`; contradictory or incomplete pairs become explicit `unknown`.

Only pregame context, identities, draft and target `result` survive into the canonical table. `gamelength` contributes solely to the conservative time at which the label is allowed to enter historical state; it is not a model feature. KDA, economic differences, damage and objectives are discarded by the ingestion whitelist.

The one-row-per-game schema is:

```text
game_id, date, available_at, league, patch, blue_win, first_pick_side
blue_team_id, blue_team_name, red_team_id, red_team_name
{blue|red}_{top|jng|mid|bot|sup}_{player_id|player_name|champion}
{blue|red}_ban{1..5}
```

Storage: `data/processed/games.parquet` and `data/processed/games.duckdb` (`games` table, unique `game_id`). The database also contains `player_registry`, `player_team_stints` and `quarantine` tables. The mandatory player/team join is `(game_id, side)` with pandas `validate='many_to_one'`. Exact duplicate records are deduplicated; conflicting duplicates, absent required identities, wrong roles, inconsistent winners, noncomplementary opposing results, champion conflicts and invalid patches are quarantined. Missing bans remain `unknown` rather than fabricated champion names or assumed omissions.

## Identity and date limitations

ChainCC's absent player IDs prevent verified global person resolution from these CSVs alone. This project assigns a persistent deterministic local `pro:<UUID>` to an exact normalized professional display name. This is a local professional-player registry, **not an official immutable player identifier**. All such rows carry `identity_basis=source_playername_unverified` in `player_registry.csv`; different names are not automatically merged, and same-name collisions inside a match are rejected. Name reuse across people, or undocumented renames, can still split or conflate history. This limitation must accompany B/C results.

If original Oracle's Elixir CSVs contain `playerid`, those source IDs take precedence. Verified manual aliases can override identity with `configs/player_aliases.csv`:

```text
canonical_id,alias,valid_from,valid_to
```

The supplied file intentionally has no guessed mappings. Add only researched mappings; dates use half-open intervals `[valid_from, valid_to)`, UTC, with empty bounds meaning unbounded. Overlapping intervals for the same exact alias fail validation. Record the evidence for each real mapping in project notes before applying it. Retrain after changing identities: a model trained on old canonical IDs is not interchangeable with the new mapping.

`player_team_stints.csv` preserves contiguous team observations with `observed_from` and `last_observed`. These are **observed appearance intervals, not official transfer-effective dates**. The system never uses future roster appearances to infer a historical team.

Source date start/end semantics and original publication times are not guaranteed. The availability estimate is `max(next UTC midnight, source date + game duration + 1 hour)`. Historical features require both `date < as_of` and `available_at < as_of`; this deliberately excludes same-day prior games and avoids treating an ongoing game as completed. `load_games` pushes these predicates into DuckDB before returning records. Backtests remain retrospective snapshots: later upstream corrections cannot be reconstructed as true historical vendor snapshots.

## Manual CSV import

[Oracle's Elixir downloads](https://oracleselixir.com/tools/downloads) returned HTTP 403 during this run. No third-party mirror was substituted. If direct downloads are unavailable, download the original yearly CSV through a browser and import it to a **separate source directory**, preserving its original filename:

```python
from worlds_predictor.data import import_manual_csv, normalize_data

import_manual_csv(
    "/absolute/path/2026_LoL_esports_match_data_from_OraclesElixir.csv",
    "data/manual_oe",
    source_url="https://oracleselixir.com/tools/downloads",
    license_text="unknown; verify current provider and underlying Riot/Leaguepedia terms",
)
normalize_data(
    "data/manual_oe", "data/processed_oe",
    as_of="2026-10-22T00:00:00Z",
    alias_path="configs/player_aliases.csv",
)
```

Use the actual current license text when verified; do not infer CC BY 4.0 for an Oracle's Elixir import from ChainCC's license. Manual provenance is marked operator-supplied and original download time unknown. The importer refuses to overwrite a different existing snapshot. Original OE files need both player rows and `position=team` rows; adapters recognize `gameid`, `teamname`, `teamid`, `firstpick`, `playerid` and standard draft columns. ChainCC manual imports need a matching player CSV and team CSV. Never mix different snapshots/providers of the same games in one raw directory without resolving conflicts.

Missing required fields produce a clear error or a quarantined game, not a guessed record. If no valid games or model remain, the API must fail closed rather than return a default probability.

## Public versus source context names

The public [Riot Worlds patch announcement](https://www.leagueoflegends.com/en-us/news/game-updates/league-of-legends-patch-26-20-notes/) calls the patch **26.20**, while the source CSV stores **16.20** for Worlds 2026 records. Riot's [Data Dragon versions endpoint](https://ddragon.leagueoflegends.com/api/versions.json) lists **16.20.1**. Their equivalence is an explicit reviewed inference from the same event and period; these two official pages do not themselves publish a direct namespace crosswalk. `reports/patch_namespace_mapping.json` records the retrieval timestamp, payload SHA-256, observed source patch groups, and official-public-announcement evidence with `evidence_type=inferred_cross_namespace_equivalence`. `configs/worlds2026.json` records this explicit approved mapping.

At the request boundary, `context.model_patch` maps either `26.20` or `16.20` onto the existing model category `16.20`. The established source major versions 14/15/16 use two-digit minor formatting, such as `16.1` → `16.01`. **No general subtraction or future-year mapping is inferred**: for example, `26.21` is not automatically converted to `16.21`.

The aliases `WLDs`, `WCS`, `Worlds` and `World Championship` (case-insensitive, optionally with a year) all map to the source/model category `WLDs`. Consequently source spellings cannot bypass the Worlds patch guard: a 2026 Worlds request using `WLDs` and `16.19` is rejected with HTTP 422. If the official check reports a conflict with configured patch, all recognized Worlds 2026 aliases receive HTTP 503 until reconciled. Equivalent `16.20` and `26.20` requests share the same model features and probabilities. This boundary normalization does not modify original records, training features, model files or evaluation results.
